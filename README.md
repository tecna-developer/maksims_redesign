# Maksims OÜ — сайт

Статический трёхъязычный сайт (ET / RU / EN). Собирается скриптом без зависимостей.

## Сборка

```bash
node build.mjs
```

Собирает `src/` → `dist/`: 6 страниц × 3 языка = 18 HTML-файлов плюс `sitemap.xml`,
`robots.txt` и статические ресурсы.

Локальный просмотр:

```bash
node build.mjs --serve
```

→ http://localhost:4173/

## Структура

```
site.config.json      домен, контакты, реквизиты, endpoint формы
src/locales/*.json    все тексты: { common: {...}, pages: { index: {...}, ... } }
src/partials/         head, header, footer, contact-band — общие для всех страниц
src/pages/            шаблоны страниц ({{key}} вместо текста)
build.mjs             генератор
dist/                 результат сборки (не редактировать руками)
styles.css  app.js    правятся здесь, копируются в dist/ при сборке
```

## Как это работает

- `{{key}}` — текст из локали (экранируется), `{{{key}}}` — HTML без экранирования,
  `{{> partial}}` — вставка партиала.
- Значения ищутся в `pages.<страница>`, затем в `common`, затем в контексте сборки
  (URL, язык, данные компании).
- Ключи, начинающиеся с `_`, сборка игнорирует в проверке неиспользуемых.
- **Сборка падает, если хотя бы в одном языке нет ключа, который использует шаблон.**
  Именно из-за отсутствия такой проверки третья колонка футера рендерилась пустой
  на четырёх страницах, а строка статистики на главной не переводилась.

## `_archive` — тексты закомментированной разметки

В `common._archive` и `pages.index._archive` лежат переведённые строки, на которые
сейчас ничего не ссылается: разметка соответствующих блоков закомментирована.
Это не мусор, а готовый копирайтинг — он понадобится, если блоки вернуть.

| где | ключи | к чему относится |
|---|---|---|
| `common._archive` | `tagline` | `<span class="brand-tag">` в шапке |
| | `footer_services_head`, `footer_people_head`, `footer_more_head` | прежние варианты названия 3-й колонки футера (заменены на `footer_who_head`) |
| `pages.index._archive` | `about_eyebrow`, `about_title`, `about_p1`, `about_p2`, `about_more` | секция «О компании» на главной |
| | `hero_eyebrow` | надпись над заголовком в герое — **только RU/EN** |
| | `news_eyebrow`, `news_title`, `news_note`, `news_all`, `why_lede` | разметки нет вообще, см. ниже |

Сама разметка закомментирована на месте — в `src/partials/header.html`,
`src/partials/footer.html` и `src/pages/index.html`. Плейсхолдеры внутри
HTML-комментариев сборка не проверяет, поэтому они спокойно там лежат.

**Чтобы вернуть блок:** раскомментировать разметку, перенести нужные ключи из
`_archive` на уровень выше и дописать недостающий эстонский. Без последнего шага
сборка упадёт — это и есть правильное поведение.

**Исключение:** у `news_*` и `why_lede` разметки не осталось нигде — соответствующие
секции были удалены, а не закомментированы. Это только тексты; блоки под них
придётся верстать заново.

## `portfolioMode` — режим витрины

`site.config.json` → `portfolioMode: true` собирает версию для портфолио.
Один флаг переключает всё сразу:

| | `true` (сейчас) | `false` (боевой сайт) |
|---|---|---|
| `<meta name="robots">` | `noindex, nofollow, noarchive` | не выводится |
| `robots.txt` | `Disallow: /`, sitemap не рекламируется | `Allow: /` + ссылка на sitemap |
| плашка в шапке | «неофициальная концепция для портфолио» | нет |
| форма | `data-mode="demo"`, кнопка `type="button"`, ничего не отправляет | `post` или `mailto` |
| пояснение под формой | «это демонстрационная форма» | нет |
| политика конфиденциальности | демо-формулировки: данные не собираются | обычный текст |

Всё это генерируется в `build.mjs`, а не прописано в партиалах. Так сделано
намеренно: при переключении на боевой режим сайт обязан вернуться в состояние,
пригодное для запуска. Забытый `noindex` выкинул бы все 18 страниц из индекса,
а забытая плашка сообщала бы клиентам, что их собственный сайт — неофициальный
макет.

Проверить перед запуском:

```bash
node -e "const c=require('./site.config.json');c.portfolioMode=false;require('fs').writeFileSync('site.config.json',JSON.stringify(c,null,2))"
node build.mjs && grep -c noindex dist/index.html   # должно быть 0
```

`sitemap.xml` собирается в обоих режимах — чтобы его можно было проверить
заранее. В режиме витрины на него никто не ссылается и `robots.txt` закрывает
доступ.

## Форма: подключение Formspree

Сейчас `formEndpoint` пуст. Пока так, форма работает в запасном режиме `mailto:` —
открывает почтовую программу посетителя, заявка не теряется. Сборка об этом
предупреждает (в `portfolioMode` предупреждение подавлено).

Чтобы подключить Formspree:

1. Создать форму на [formspree.io](https://formspree.io) с получателем `info@maksims.ee`
2. Скопировать её endpoint — вида `https://formspree.io/f/xxxxxxxx`
3. Прописать в `site.config.json` **оба** поля:

```json
"formEndpoint": "https://formspree.io/f/xxxxxxxx",
"company": { "formProvider": "Formspree" }
```

Разметка уже под это готова, менять ничего не нужно:

- поле с именем `email` Formspree использует как Reply-To — ответ на уведомление
  уходит напрямую отправителю, отдельный `_replyto` не нужен;
- скрытое `_subject` задаёт тему письма;
- `app.js` шлёт `Accept: application/json`, поэтому посетитель остаётся на
  странице, и разбирает формат ошибок Formspree `{ errors: [{ message }] }`,
  показывая сообщение сервиса вместо общей заглушки;
- ловушка для ботов (`website`) отсекает отправку до запроса.

`company.formProvider` — не косметика: от него зависит формулировка в политике
конфиденциальности, которая обязана описывать то, что происходит на самом деле.

| `formProvider` | раздел «Передача третьим лицам» |
|---|---|
| пусто | форма открывает почтовую программу посетителя, сторонние сервисы не участвуют |
| задан | запросы доставляет поставщик услуги «…», исключительно для доставки |
| — | в `portfolioMode` перекрывается: форма ничего не отправляет и не хранит |

Оговорка: AJAX-отправка на бесплатном тарифе Formspree исторически была
ограничена. Если форма начнёт уходить на их страницу «Thank You» вместо
инлайн-сообщения — дело в тарифе, а не в коде.

## Прочее

- `uudised.html` собирается и попадает в sitemap, но из шапки убран — ссылка
  осталась только в футере.
- `/` и `/index.html` оба отдают 200. `canonical` указывает на `/index.html`,
  так что склейка работает. Если захочется адресов без расширения — это
  `cleanUrls` в `vercel.json` плюс правка `pathFor()`, `canonical`, `hreflang`
  и `sitemap` разом; сейчас схема сохраняет существующие `.html`-адреса.
